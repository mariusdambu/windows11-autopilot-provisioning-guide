A practical English guide for creating a Windows 11 Autopilot installation USB, pre-provisioning a laptop, validating the user setup, and handling older devices that require a hardware hash import.

1. Scope

This procedure is intended for technicians preparing organization-managed laptops with a Windows 11 Autopilot ISO and USB media. It covers the DISM-based image workflow, the installation screens, the Autopilot pre-provisioning flow, and the supporting technician USB scripts used to collect hardware hashes and run diagnostics.

The expected end state is a Windows 11 laptop that has completed Autopilot pre-provisioning, has been resealed, and is ready for the assigned user to sign in with MFA.

2. Before you start

Required downloads and tools

  • Download the latest official Windows 11 ISO from Microsoft: Windows 11 download.
  • Use a Windows technician PC with administrator rights. DISM is included with Windows and is normally enough for mounting images, injecting drivers, and committing the WIM.
  • Use only vendor drivers. Do not inject apps, scripts, language packs, or modified ISO content into the base image.
Optional ADK tools Only needed for ADK-specific tools such as oscdimg or WinPE media creation. Show details Hide details v

Windows ADK is not required for normal DISM mounting, driver injection, or committing a WIM when using the tools already included with Windows. Install ADK only if you need ADK-specific deployment tools such as oscdimg, WinPE media creation, or other deployment tooling.

Microsoft reference: ADK installation guide.

Do not use corporate network access during provisioning. Use an approved external Wi-Fi, approved guest Wi-Fi, or another approved non-corporate network. Do not use corporate Wi-Fi, a corporate wired network, or any network path that would make the laptop join internal resources before Autopilot has completed.
Do not use a corporate-managed laptop as the technician workstation. Use an unmanaged laptop, or a company spare laptop with a clean, original Windows 11 installation preinstalled, to prepare and run this process.

User and portal checks

3. Build the ISO with DISM

Engineers can build the image using DISM when automation is not available or when full manual control is required. The examples below use the same C:\Lab_Win11\Trabajo working-folder convention as the recommended automation path. The example driver folder uses a Lenovo T14, but the same pattern applies to other supported models.

Recommended simpler path: for most technicians, the fastest and least error-prone option is to automate the DISM workflow and ISO generation with mariusdambu/Lab_Win11. Use the manual DISM commands when you need full control or when automation is not available.
This driver-injection step is optional but useful. Technicians can use the original Windows 11 ISO or USB. If Wi-Fi drivers are not injected, Windows may not detect the laptop Wi-Fi adapter during setup or OOBE, so the technician may need to load or install the correct Wi-Fi driver manually.

Prepare the Lab_Win11 folders

Download the ZIP from the official GitHub repository and extract it to a local folder, for example C:\Lab_Win11. Use the Trabajo folder structure for all deployment payload exactly like this: 

C:\Lab_Win11
C:\Lab_Win11\Trabajo\ISOs      - Windows ISO files
C:\Lab_Win11\Trabajo\images    - boot.wim, install.wim, install.esd or install*.swm
C:\Lab_Win11\Trabajo\Drivers   - extracted INF drivers
C:\Lab_Win11\Trabajo\packages  - CAB/MSU packages
Folder rule: keep real working files in the four folders above. DISM still needs an empty temporary mount folder; for manual commands use C:\Lab_Win11\Trabajo\offline and keep it empty before mounting.

Copy the Windows image files from the ISO

Put the original Windows 11 ISO in C:\Lab_Win11\Trabajo\ISOs, then mount it in Windows. In the mounted ISO, open the sources folder and copy the image files to C:\Lab_Win11\Trabajo\images.

From mounted Windows ISO Copy to Lab_Win11
sources\boot.wim C:\Lab_Win11\Trabajo\images\boot.wim
sources\install.wim, install.esd, or all install*.swm files C:\Lab_Win11\Trabajo\images\

These files are the input for either the Lab_Win11 automation or the manual DISM commands. The manual examples assume install.wim. If the ISO contains install.esd or split install*.swm files, use the Lab_Win11 helper flow to prepare the working image, or adjust the DISM commands accordingly.

Inject vendor drivers

The technician is responsible for identifying the exact laptop model, finding the correct official driver pack, downloading it, and using it for the image. Use the vendor's official support site, for example Lenovo Support for Lenovo models, Dell Support for Dell models, HP Support for HP models, and so on.

Place the downloaded model-specific drivers in a folder, for example:

C:\Lab_Win11\Trabajo\Drivers\T14
Manual DISM commands Open this only when you need to mount the image, inject drivers, and commit manually. Show commands Hide commands v

Mount the install.wim

dism /Get-WimInfo /WimFile:"C:\Lab_Win11\Trabajo\images\install.wim"
dism /Mount-Image /ImageFile:"C:\Lab_Win11\Trabajo\images\install.wim" /Index:6 /MountDir:"C:\Lab_Win11\Trabajo\offline" /CheckIntegrity
Index check: Windows 11 Pro is usually index 6. Always confirm the correct index with /Get-WimInfo before mounting.

Inject drivers into the mounted image

Run this command after the image is mounted:

dism /Image:"C:\Lab_Win11\Trabajo\offline" /Add-Driver /Driver:"C:\Lab_Win11\Trabajo\Drivers\T14" /Recurse

Optional: inject Windows packages

Only use this if approved CAB or MSU packages are required. Place them under C:\Lab_Win11\Trabajo\packages and add them from there before committing the image. 

dism /Image:"C:\Lab_Win11\Trabajo\offline" /Add-Package /PackagePath:"C:\Lab_Win11\Trabajo\packages"

Commit and unmount

dism /Unmount-Image /MountDir:"C:\Lab_Win11\Trabajo\offline" /Commit /CheckIntegrity

After injecting drivers

After committing the image, rebuild the deployment media before installing Windows. Use one of these two paths:

  • ISO path: use the automated ISO creation option. It uses the base ISO from Trabajo\ISOs, the updated images from Trabajo\images, and writes the final ISO back to Trabajo\ISOs.
  • USB path: recreate or update the bootable USB. Replace sources\boot.wim on the FAT32 boot partition with Trabajo\images\boot.wim. Replace the install image in the exFAT partition's sources folder with the updated Trabajo\images\install.wim or equivalent install.* files.
Advanced: rebuild ISO manually with ADK tools Only if you are not using the automated ISO creation option. Show details Hide details v

If you need to generate a new ISO file manually, use oscdimg. This tool is part of the Windows ADK Deployment Tools. In this workflow, keep the base Windows ISO in Trabajo\ISOs, keep customized boot.wim and install.* files in Trabajo\images, and save the generated ISO back to Trabajo\ISOs.

Recommended: use the automated ISO creation option. It reads the base ISO from Trabajo\ISOs, uses custom images from Trabajo\images, prepares the temporary media internally, and writes the final ISO to Trabajo\ISOs.

4. Create the bootable USB

Use the Microsoft-documented two-partition USB layout below as the primary method. This keeps the boot partition simple and the Windows setup files separate from the large image files. Rufus can still be used as an optional shortcut when you are selecting a prepared ISO, but the resulting USB must match the required structure.

USB recommendation: use a pendrive of at least 16 GB. A USB 3.0 or faster drive is strongly recommended to reduce copy and installation time.

Run the commands one line at a time. First list the disks:

Get-Disk

Identify the USB disk number from the output. The commands below use Disk 5 as an example. If your USB appears as another disk number, replace 5 with the real USB disk number in every command before copying or running it.

Verify the example disk number before wiping anything:

Get-Disk -Number 5 | Format-List Number,FriendlyName,SerialNumber,Size,BusType
Disk number warning: the commands below erase the selected disk. Only continue if Disk 5 is the USB drive. If the USB is shown as Disk 2, Disk 3, or any other number, change the number in every command first. Never run these commands against the internal laptop disk. 
Clear-Disk -Number 5 -RemoveData -RemoveOEM
Set-Disk -Number 5 -PartitionStyle GPT
New-Partition -DiskNumber 5 -Size 2048MB -AssignDriveLetter | Format-Volume -FileSystem FAT32
New-Partition -DiskNumber 5 -UseMaximumSize -AssignDriveLetter | Format-Volume -FileSystem exFAT

Required partition structure

Use two partitions. The first partition is only the UEFI boot starter. The second partition contains the full Windows setup content. Microsoft documents FAT32 as the default WinPE/UEFI boot format and calls out the 4 GB FAT32 file-size limit for Windows images; this guide keeps the boot partition FAT32 and uses exFAT for the larger data partition so technicians can copy files easily from Windows or macOS.

Microsoft references: Create bootable Windows PE media and Use a multi-partition USB deployment drive.

Do not copy the full sources folder to the FAT32 partition. The FAT32 partition should only contain sources\boot.wim. Put the full sources folder, including the large Windows image file, on the exFAT partition.

5. Install Windows from USB

  1. Boot the laptop from the USB device. On Lenovo devices, press F12 for the boot menu.
  2. Select the USB boot device.
  3. Choose the language, regional format, and keyboard layout required for the deployment.
  4. Select Install Windows 11 and acknowledge that files, apps, and settings will be deleted.
  5. Accept the Microsoft software license terms.
  6. Before selecting the installation target, wipe the internal disk if the laptop must start from a clean state. Use DiskPart clean, the workbench wipe option, or the Windows Setup delete partitions option.
  7. Use DiskPart or the setup UI to clean/select the installation disk as required.
  8. Select the target partition and start the Windows installation.
Disk wipe warning: verify the disk number before running clean or Clear-Disk. These actions destroy data.

6. OOBE and Autopilot pre-provisioning

  1. Complete the country/region and keyboard screens.
  2. When asked for a network, connect only to an approved external Wi-Fi, approved guest Wi-Fi, or other approved non-corporate network.
  3. When the work or school setup screen appears, confirm the user has the required Azure group memberships before continuing.
  4. At the work or school sign-in screen, before entering or connecting the user's account, press the Windows key five times to open the provisioning options.
  5. Select Pre-provision with Windows Autopilot, then select Next.
  6. Wait until all profiles, policies, and applications finish installing.
  7. When the completion screen appears, select Reseal.
  8. The device reboots to the login screen. Ask the user to sign in with their corporate email and password, with Authenticator ready for MFA.
Command Prompt shortcut: at the first Windows setup screen, press Shift + F10. On laptops where the function row requires the Fn modifier, press Fn + Shift + F10.

7. Post-setup validation and Intune task

After the user signs in and MFA is complete, validate the laptop before handing it over.

  • The required security client is installed and connected.
  • The device management portal is installed, the user is signed in, and the device is compliant.
  • The required productivity apps are installed and the mail profile is syncing.
  • The printer is installed and printing.
  • Network drives are mapped and accessible.
  • All required applications open correctly.
  • Quick Assist or Remote Help is present.
  • Access to company resources is confirmed.
  • No enrollment or compliance errors are visible.

Enable corporate Wi-Fi after successful setup

  1. Go to Intune: https://intune.microsoft.com.
  2. Search for the group <Temporary corporate Wi-Fi exclusion group>.
  3. Remove the computer account from that group's members.
  4. Confirm that the laptop can now use the corporate Wi-Fi.

If you do not have permissions or need clarification, follow the approved company escalation matrix for endpoint engineering support.

8. Older laptops and hardware hash capture

Some older laptops are not enrolled in Autopilot by default. Before requesting enrollment, collect the device hardware hash and upload the CSV file to the required location.

Required HWID process

  1. Prepare the technician USB.
  2. Rename the USB volume label to exactly AUTOPILOTUSB. The script searches for this label; if it is wrong, the CSV will not be copied back to the USB correctly.
  3. For Option A, connect the laptop to an approved Wi-Fi or approved non-corporate network with internet access before running the HWID capture.
  4. Run Run-HWID.cmd or option 4 - HWID Option A from safeworkbench-en.cmd.
  5. Option A creates C:\HWID, downloads/updates Get-WindowsAutopilotInfo from PowerShell Gallery, and exports a CSV.
  6. If Wi-Fi cannot be connected or the PowerShell Gallery download fails, use Option B instead.
  7. Do not open or edit the HWID CSV in Excel. Upload the generated CSV unchanged.
  8. When the USB label is correct, the file is copied to HardwareIDs\<Serial>-HWID.csv on the USB.
  9. Upload the hardware hash CSV to <approved internal Autopilot HWID upload path>.
  10. Then follow the approved company escalation matrix to request Autopilot enrollment.
Option A needs internet. The scripts\Get-WindowsAutoPilotInfo.ps1 workflow downloads or updates Get-WindowsAutopilotInfo from PowerShell Gallery, so the laptop must already be connected to an approved Wi-Fi or approved non-corporate network before running it. It only generates a local CSV and copies it to the USB; it does not upload the CSV to Intune and does not enroll the device. If Wi-Fi cannot be connected or the download fails, use Option B.
Option B works offline. The GetAutoPilot\GetAutoPilot.CMD helper runs from the technician USB without internet access and saves the CSV in the GetAutoPilot folder.

9. Technician USB tools reference

This project includes the technician USB tools under tools\technician-usb. Copy the contents of that folder to the root of the technician USB and keep the folder structure exactly as provided.

  1. Copy everything inside tools\technician-usb to the root of the USB.
  2. Keep the scripts and GetAutoPilot folders next to the CMD files.
  3. Create a folder called HardwareIDs at the root of the USB.
  4. Rename the USB volume label to exactly AUTOPILOTUSB before running HWID capture.
  5. Run safeworkbench-en.cmd as the preferred menu.
Disk wipe warning: option 3 in the workbench wipes Disk 0. Use safeworkbench-en.cmd unless you have a specific reason not to; it requires typing ERASE before the wipe runs.
File Purpose Notes
safeworkbench-en.cmd Recommended technician menu. English UI. Use this first. Adds a shutdown/restart delay and requires typing ERASE before wiping Disk 0.
workbench-en.cmd Standard technician menu. English UI. Option 3 wipes Disk 0 through clean_disk0.txt; use carefully.
Run-HWID.cmd Runs the hardware hash capture script. Calls scripts\Get-WindowsAutoPilotInfo.ps1. Requires approved Wi-Fi/internet access, PowerShell Gallery access, and the USB label AUTOPILOTUSB.
Run-AutopilotDiagnostics.cmd Runs Autopilot diagnostics. Calls scripts\Get-AutopilotDiagnosticsCommunity.ps1.
GetAutoPilot\GetAutoPilot.CMD Additional second option for hardware hash export. Custom offline helper. Saves CSV output in the GetAutoPilot folder. It does not upload to Intune or enroll the device.

Option A - recommended HWID workflow

  1. After downloading or cloning this project, copy everything inside tools\technician-usb to the root of the technician USB.
  2. Confirm the USB root contains safeworkbench-en.cmd, scripts\, GetAutoPilot\, and HardwareIDs\.
  3. Rename the USB volume label to exactly AUTOPILOTUSB.
  4. Connect the laptop to an approved Wi-Fi or approved non-corporate network with internet access before running Option A.
  5. Boot or open Command Prompt on the target laptop.
  6. Open the technician USB drive.
  7. Run safeworkbench-en.cmd.
  8. Select option 4 - HWID Option A - Online PowerShell Gallery.
  9. If Wi-Fi cannot be connected or Option A cannot download from PowerShell Gallery, use B - HWID Option B - Offline GetAutoPilot helper.
  10. Confirm that the CSV appears in HardwareIDs\<Serial>-HWID.csv on the USB.
  11. Upload the CSV to the approved Autopilot HWID upload location.
Option B - additional GetAutoPilot helper Offline fallback when Wi-Fi is not available or Option A cannot download. Show details Hide details v
  1. After downloading or cloning this project, copy everything inside tools\technician-usb to the root of the technician USB.
  2. Keep the GetAutoPilot folder at the USB root.
  3. Run safeworkbench-en.cmd and select B - HWID Option B - Offline GetAutoPilot helper, or open the GetAutoPilot folder and run GetAutoPilot.CMD directly.
